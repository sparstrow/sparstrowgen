# Computer pairing entry — 2026-09-13

First round for where pairing should appear. The owner rejected all three as the lasting structure
after deciding computers need their own product destination and profile so the capability can grow.

| | Direction | Optimised for | Outcome |
|---|---|---|---|
| A | Conversation-first | Keeping setup inside the familiar Chat shell | rejected: pairing should live under a separate Machines menu |
| B | Focused setup | Maximum clarity during first connection | rejected: a temporary setup page does not provide a durable machine home |
| C | Context panel | Reading Chat while repairing the connection | rejected: a side panel does not scale into the requested machine profile |

## What this told us about taste

An operational entity expected to gain capabilities should have a stable destination and profile,
not remain embedded in the screen that happens to need it first. The owner explicitly wants a
Machines sidebar entry and a machine profile because the feature will be enhanced later.
